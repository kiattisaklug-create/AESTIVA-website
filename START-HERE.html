คู่มือดูแลเว็บไซต์ AESTIVA

เขียนสำหรับคนที่ไม่เคยทำเว็บมาก่อน ทำตามทีละข้อได้เลย ไม่ต้องรู้เรื่องโค้ด

สารบัญ
  1. ภาพรวม: ไฟล์อะไรอยู่ตรงไหน
  2. ส่งเว็บใหม่ขึ้น GitHub และ Railway (ทำครั้งแรกครั้งเดียว)
  3. แก้ข้อมูลในเว็บเอง (ราคา, ติดต่อ, อัปเดต, คลินิก, FAQ)
  4. เพิ่มโลโก้คลินิกที่ใช้ระบบ
  5. เปลี่ยนสีของเว็บ
  6. ถ้ามีอะไรผิดพลาด
  7. ระบบนับสถิติเว็บไซต์ (ตั้งค่าครั้งแรก และวิธีดูผล)

1) ภาพรวม: ไฟล์อะไรอยู่ตรงไหน

ไฟล์ / โฟลเดอร์หน้าที่ต้องแก้ไหม
content.jsข้อมูลที่เปลี่ยนบ่อย: ช่องทางติดต่อ, ราคา, เวอร์ชัน/อัปเดต, คลินิกที่ใช้, FAQแก้ไฟล์นี้ไฟล์เดียวเป็นหลัก
index.htmlโครงหน้าเว็บและข้อความส่วนหัว ส่วนตัวอย่างระบบนานๆ ครั้ง
styles.cssสี ตัวอักษร ระยะห่าง เอฟเฟกต์ถ้าอยากเปลี่ยนสี (ข้อ 5)
script.js, server.js, package.json, pulse.js, analytics.js, stats.htmlระบบเบื้องหลัง (รวมถึงระบบนับสถิติ)ห้ามแก้
assetsรูปภาพ โลโก้ ฟอนต์เพิ่มโลโก้คลินิกได้ (ข้อ 4)

2) ส่งเว็บใหม่ขึ้น GitHub และ Railway (ทำครั้งแรกครั้งเดียว)

วิธีนี้ไม่ต้องติดตั้งโปรแกรมอะไรเพิ่ม ใช้แค่เบราว์เซอร์

ขั้นที่ A: เตรียมไฟล์บนเครื่อง

  1. ดาวน์โหลดไฟล์ AESTIVA-website.zip ที่ได้รับ
  2. คลิกขวาที่ไฟล์ zip เลือก Extract All… (แตกไฟล์ทั้งหมด) แล้วกด Extract
  3. เปิดโฟลเดอร์ AESTIVA-website ที่ได้ จะเห็นไฟล์ index.html, styles.css, content.js และโฟลเดอร์ assets
  4. ลองดับเบิลคลิก index.html เว็บจะเปิดในเบราว์เซอร์ให้ดูก่อนได้เลย

ขั้นที่ B: อัปโหลดขึ้น GitHub

  1. เปิด https://github.com/kiattisaklug-create/AESTIVA-website แล้วล็อกอิน
  2. กดปุ่ม Add file (สีเทา ด้านขวาบน) แล้วเลือก Upload files
  3. เปิดโฟลเดอร์ AESTIVA-website บนเครื่อง กด Ctrl + A เพื่อเลือกทุกไฟล์และทุกโฟลเดอร์ข้างใน แล้วลากทั้งหมดมาวางในหน้า GitHub
  4. รอจนไฟล์ขึ้นครบ (โฟลเดอร์ assets จะขึ้นเป็นรายการไฟล์ย่อยด้วย)
  5. เลื่อนลงล่างสุด ช่อง Commit changes พิมพ์ข้อความสั้นๆ เช่น redesign website
  6. กดปุ่มสีเขียว Commit changes
ไฟล์ชื่อเดิม (เช่น index.html) จะถูกแทนที่ด้วยไฟล์ใหม่โดยอัตโนมัติ ส่วนไฟล์เก่าที่ไม่ได้ใช้แล้ว (เช่น assets/brand-reference.png) จะยังค้างอยู่ ไม่มีผลเสียกับเว็บ ลบทิ้งภายหลังได้ถ้าต้องการ

ขั้นที่ C: ให้ Railway อัปเดตเว็บ

  1. เปิดโปรเจกต์ Railway ของคุณ แล้วคลิกที่บริการ (service) ของเว็บ AESTIVA
  2. ไปที่แท็บ Settings ดูหัวข้อ Source ต้องเห็นชื่อ repo kiattisaklug-create/AESTIVA-website
  3. ถ้าเชื่อมไว้แล้ว Railway จะเริ่ม Deploy เองภายในไม่กี่วินาทีหลัง Commit ไปดูที่แท็บ Deployments รอจนขึ้นสถานะ Active (ประมาณ 1–2 นาที)
  4. เปิด https://aestiva-website-production.up.railway.app/ แล้วกด Ctrl + F5 เพื่อรีเฟรชแบบล้างแคช
ถ้าใน Source ไม่มีชื่อ repo ให้กด Connect Repo เลือก AESTIVA-website และ branch main จากนั้นระบบจะ Deploy ให้

3) แก้ข้อมูลในเว็บเอง

วิธีที่ง่ายที่สุด: แก้ไฟล์ content.js บนเว็บ GitHub ตรงๆ ไม่ต้องดาวน์โหลดอะไร

  1. เปิด https://github.com/kiattisaklug-create/AESTIVA-website
  2. คลิกไฟล์ content.js
  3. กดรูป ดินสอ (Edit this file) ด้านขวาบนของกล่องไฟล์
  4. แก้ข้อความ ตามตัวอย่างด้านล่าง
  5. กดปุ่มสีเขียว Commit changes… แล้วกด Commit changes อีกครั้งในหน้าต่างที่ขึ้นมา
  6. รอประมาณ 1–2 นาที Railway จะอัปเดตเว็บให้เอง แล้วรีเฟรชหน้าเว็บ (Ctrl + F5)
กติกา 4 ข้อ ก่อนแก้ทุกครั้ง
  1. แก้เฉพาะข้อความที่อยู่ในเครื่องหมายคำพูด "..." หรือตัวเลขราคาเท่านั้น
  2. ห้ามลบเครื่องหมาย , ที่ท้ายบรรทัด
  3. ห้ามลบเครื่องหมาย { } [ ]
  4. บรรทัดที่ขึ้นต้นด้วย // คือหมายเหตุ ไม่มีผลกับหน้าเว็บ

ตัวอย่างที่แก้บ่อย

เปลี่ยนราคา หาชื่อแพ็กเกจ แล้วแก้ตัวเลขหลัง price: (ใส่ตัวเลขล้วน ไม่ต้องมี ฿ หรือ ,)

name: "Pro",
price: 2490,      ← เปลี่ยนเป็น 2790

เพิ่มเบอร์โทรหรืออีเมล ใส่ค่าในเครื่องหมายคำพูด ระบบจะแสดงให้เองในหัวข้อติดต่อและท้ายเว็บ

phone: "081-234-5678",
email: "hello@aestiva.co.th",

ประกาศอัปเดต / เวอร์ชันใหม่ แก้ latestVersion และแก้ข้อความในหัวข้อ updates

latestVersion: "V1.1",

ถ้าจะเพิ่มรายการอัปเดตใหม่ ให้คัดลอกทั้งบล็อกตั้งแต่ { ถึง }, ของรายการเดิมไปวางต่อท้าย แล้วแก้ข้อความ

เพิ่มคลินิกที่ใช้ระบบ (แนะนำให้ขออนุญาตคลินิกก่อนเผยแพร่ชื่อและโลโก้) หาหัวข้อ clinics: [ แล้วเพิ่มบล็อกตามนี้ระหว่าง [ กับ ]

clinics: [
  {
    name: "ชื่อคลินิก",
    logo: "",
    note: "กรุงเทพฯ"
  },
  {
    name: "อีกคลินิกหนึ่ง",
    logo: "",
    note: "เชียงใหม่"
  },
],

เมื่อมีคลินิกอย่างน้อย 1 แห่ง ข้อความ "กำลังเปิดตัวร่วมกับคลินิกพันธมิตร" จะหายไปเอง และแสดงเป็นการ์ดชื่อคลินิกแทน

เพิ่มคำถามที่พบบ่อย คัดลอกบล็อก { q: "...", a: "..." }, ของเดิมไปวางต่อท้ายในหัวข้อ faq แล้วแก้คำถามและคำตอบ

อยากดูผลก่อนขึ้นเว็บจริง

  1. ดาวน์โหลดโฟลเดอร์เว็บลงเครื่อง (ตามข้อ 2 ขั้น A)
  2. คลิกขวาที่ content.js เลือก Open with แล้วเลือก Notepad
  3. แก้ข้อความ แล้วกด Ctrl + S
  4. ดับเบิลคลิก index.html เพื่อดูผล ถ้ามีแถบสีแดงขึ้นด้านบนของหน้า แปลว่ามีเครื่องหมายหายหรือเกิน ให้ตรวจตามกติกา 4 ข้อ
  5. พอพอใจแล้ว ค่อยอัปโหลดไฟล์ content.js ขึ้น GitHub (Add file → Upload files → ลากไฟล์ที่แก้ → Commit changes)

4) เพิ่มโลโก้คลินิกที่ใช้ระบบ

  1. เตรียมไฟล์โลโก้เป็น .png พื้นโปร่งใส หรือ .jpg ตั้งชื่อเป็นภาษาอังกฤษไม่มีเว้นวรรค เช่น clinic-a.png
  2. เปิด GitHub → คลิกโฟลเดอร์ assets → Add file → Upload files → ลากไฟล์โลโก้มาวาง → Commit changes
  3. เปิด content.js (ตามข้อ 3) แล้วใส่ชื่อไฟล์ในช่อง logo
{
  name: "ชื่อคลินิก",
  logo: "assets/clinic-a.png",
  note: "กรุงเทพฯ"
},

5) เปลี่ยนสีของเว็บ

  1. เปิดไฟล์ styles.css (บน GitHub กดรูปดินสอเหมือนข้อ 3)
  2. ที่ส่วนบนสุดจะมีกลุ่มสี เช่น --gold: #D4AF37; เปลี่ยนรหัสสีตรงนั้น ทั้งเว็บจะเปลี่ยนตาม
  3. แก้เฉพาะรหัสสีหลัง : (ขึ้นต้นด้วย #) อย่าลบเครื่องหมาย ;

6) ถ้ามีอะไรผิดพลาด

อาการวิธีแก้
แก้แล้วเว็บจริงไม่เปลี่ยนรอ 2 นาที แล้วกด Ctrl + F5 และเช็คแท็บ Deployments ใน Railway ว่าขึ้น Active
Railway ขึ้น Failedมักเกิดจากแก้ไฟล์ script.js, server.js หรือ package.json โดยไม่ตั้งใจ ให้กลับไปที่ GitHub เปิดไฟล์นั้น กด History แล้วย้อนกลับเป็นเวอร์ชันก่อนหน้า
ตอนเปิดด้วยดับเบิลคลิกมีแถบแดงด้านบนเครื่องหมาย , " " { } [ ] ใน content.js หายหรือเกิน ดูบรรทัดที่เพิ่งแก้
แก้ผิดจนไม่รู้จะแก้ยังไงเปิด content.js บน GitHub กด History เลือกเวอร์ชันก่อนหน้า แล้วกด <> เพื่อดูไฟล์เดิม คัดลอกมาวางทับได้

ทุกครั้งที่ Commit GitHub จะเก็บประวัติไว้ ย้อนกลับได้เสมอ จึงลองแก้ได้อย่างสบายใจ

7) ระบบนับสถิติเว็บไซต์ (ตั้งค่าครั้งแรก และวิธีดูผล)

ระบบนี้นับว่ามีคนเข้าเว็บกี่ครั้ง คนเลื่อนไปถึงส่วนไหน กดปุ่ม/แท็บอะไรมากที่สุด คนมาจาก TikTok / Instagram / LINE หรือที่อื่น และใช้มือถือหรือคอม โดยไม่ใช้คุกกี้และไม่เก็บข้อมูลส่วนตัว ดูผลได้ที่หน้าลับ /stats ซึ่งต้องใส่รหัสผ่านก่อนเข้า

ลำดับที่แนะนำ: ทำขั้น A และ B ใน Railway ก่อน แล้วค่อยทำขั้น C (อัปโหลดไฟล์ขึ้น GitHub) เพื่อให้ข้อมูลถูกเก็บถาวรตั้งแต่คนแรกที่เข้าเว็บ

ขั้นที่ A: เพิ่ม Volume (ที่เก็บข้อมูลถาวร) บน Railway

ถ้าไม่ทำขั้นนี้ ข้อมูลสถิติจะหายทุกครั้งที่อัปเดตเว็บ

  1. เปิดโปรเจกต์ Railway ของเว็บ AESTIVA จะเห็นกล่องบริการของเว็บอยู่บนพื้นที่ว่าง (canvas)
  2. คลิกขวาที่พื้นที่ว่างข้างๆ กล่อง แล้วเลือก Volume (หรือกด Ctrl + K พิมพ์คำว่า volume แล้วเลือก Create Volume)
  3. เมื่อมีหน้าต่างถามว่าจะต่อกับบริการไหน ให้เลือกบริการเว็บ AESTIVA
  4. ช่อง Mount path พิมพ์ /data แล้วกดสร้าง (Create / Add)
  5. Railway จะ Deploy ใหม่ให้เองสั้นๆ รอจนสถานะเป็น Active

ขั้นที่ B: ตั้งรหัสผ่านสำหรับหน้าสถิติ

  1. คลิกที่กล่องบริการเว็บ AESTIVA แล้วเปิดแท็บ Variables
  2. กด New Variable
  3. ช่องชื่อ (Name) พิมพ์ STATS_PASSWORD (ตัวพิมพ์ใหญ่ทั้งหมด)
  4. ช่องค่า (Value) พิมพ์รหัสผ่านที่คุณต้องการ ควรยาวอย่างน้อย 12 ตัว ผสมตัวอักษรกับตัวเลข และไม่ซ้ำกับรหัสอื่นที่ใช้อยู่ จดเก็บไว้ในที่ปลอดภัย
  5. กด Add แล้วกด Deploy ถ้ามีปุ่มขึ้นมา รอจนสถานะเป็น Active
ห้ามเขียนรหัสผ่านลงในไฟล์ใดๆ ในโฟลเดอร์เว็บ เพราะ GitHub ของคุณเป็น Public ให้ใส่ที่ Railway Variables เท่านั้น

ขั้นที่ C: อัปโหลดไฟล์ใหม่ขึ้น GitHub

ไฟล์ชุดอัปเดตอยู่ในโฟลเดอร์ AESTIVA-stats-update (ไม่มี content.js อยู่ในชุดนี้ ข้อมูลที่คุณแก้ไว้จึงไม่ถูกทับ)

  1. แตกไฟล์ AESTIVA-stats-update.zip (คลิกขวา → Extract All)
  2. เปิด https://github.com/kiattisaklug-create/AESTIVA-website กด Add file → Upload files
  3. เปิดโฟลเดอร์ที่แตกไฟล์ กด Ctrl + A เลือกทุกไฟล์ ลากมาวางในหน้า GitHub
  4. ช่อง Commit พิมพ์ว่า add analytics แล้วกด Commit changes
  5. รอ Railway Deploy 1–2 นาที จนสถานะเป็น Active

ขั้นที่ D: เปิดดูสถิติ

  1. เปิด https://aestiva-website-production.up.railway.app/stats
  2. เบราว์เซอร์จะมีหน้าต่างถามชื่อผู้ใช้และรหัสผ่าน ช่องชื่อผู้ใช้พิมพ์อะไรก็ได้ เช่น admin ส่วนช่องรหัสผ่านพิมพ์ค่าที่ตั้งไว้ในขั้น B
  3. เก็บลิงก์นี้ไว้ใน Bookmark ของเบราว์เซอร์ (บนมือถือ: เมนูแชร์ → Add to Home Screen)
ถ้าเปิดแล้วเห็นข้อความ "ยังไม่ได้ตั้งรหัสผ่าน" แปลว่าขั้น B ยังไม่สำเร็จ ให้ตรวจว่าชื่อตัวแปรพิมพ์ถูกต้องและกด Deploy แล้ว ถ้าเห็นแถบเหลือง "ยังไม่ได้ต่อ Volume" แปลว่าขั้น A ยังไม่สำเร็จ

ขั้นที่ E: ไม่ให้นับการเข้าเว็บของตัวเอง

  1. บนมือถือและคอมที่คุณใช้ เปิดลิงก์ https://aestiva-website-production.up.railway.app/?notrack=1 ครั้งเดียวต่อเครื่อง
  2. หลังจากนั้นเครื่องนั้นจะไม่ถูกนับอีก (ยกเลิกได้โดยเปิด ?notrack=0)

ขั้นที่ F: ใช้ลิงก์แยกช่องทาง (ทำให้รู้ว่าคนมาจากไหนแม่นยำขึ้น)

TikTok และ Instagram มักไม่บอกว่าคนมาจากไหน จึงให้ใส่ลิงก์ที่ต่อท้ายด้วยชื่อช่องทาง:

วิธีใช้ข้อมูลปรับปรุงเว็บ

  • ส่วนที่คนเลื่อนไปถึง: ถ้าคนหายไปเยอะที่ส่วนไหน ลองย่อส่วนนั้นให้สั้นลงหรือย้ายเนื้อหาสำคัญขึ้นไปก่อนหน้า
  • ปุ่มและแท็บที่ถูกกดมากที่สุด: บอกว่าลูกค้าสนใจอะไร เช่น ถ้าแท็บ LINE OA ถูกเปิดบ่อย ให้ขยายเนื้อหาส่วนนั้น
  • อัตราการติดต่อ: เทียบก่อนและหลังแก้เว็บ เพื่อดูว่าที่แก้ไปได้ผลไหม
  • ช่วงเวลาที่มีคนเข้า: ใช้เลือกเวลาโพสต์ TikTok / Instagram
  • ข้อมูลน้อยกว่า 30–50 ครั้ง ยังไม่ควรใช้ตัดสินใจ ให้รอสะสม 2–4 สัปดาห์

ข้อควรรู้

  • ผู้เข้าชมนับเป็นรายวัน คนเดิมที่กลับมาวันถัดไปจะนับเป็นอีกคน (เพราะระบบไม่ใช้คุกกี้เพื่อความเป็นส่วนตัว)
  • คนที่เปิด Do Not Track หรือใช้ตัวบล็อกโฆษณาบางตัวจะไม่ถูกนับ ตัวเลขจริงจึงอาจสูงกว่าที่เห็นเล็กน้อย
  • ท้ายหน้าเว็บมีข้อความแจ้งผู้เข้าชมว่า "เว็บนี้เก็บสถิติการเข้าชมแบบไม่ระบุตัวตน ไม่ใช้คุกกี้" หากต้องการนโยบายความเป็นส่วนตัวฉบับเต็ม ควรให้ผู้เชี่ยวชาญด้านกฎหมาย PDPA ตรวจ
  • ถ้าลืมรหัสผ่าน: ไปที่ Railway → Variables → แก้ค่า STATS_PASSWORD เป็นรหัสใหม่ แล้ว Deploy
  • ถ้ากรอกรหัสผิดหลายครั้งติดกัน ระบบจะล็อกให้รอ 15 นาที
